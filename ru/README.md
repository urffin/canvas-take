# CanvasTake

[English](../README.md)

Независимая TypeScript-библиотека для записи видео с HTML canvas с необязательными
аудиодорожками и покадрового экспорта GIF через отдельную точку входа. Без внешних
зависимостей во время выполнения и без зависимости от AlgiViz. Только ESM,
с декларациями TypeScript. Лицензия MIT. Пакет не запускает и не рисует вашу анимацию.

## Установка

```sh
npm install @grundyjs/canvas-take
```

## Запись canvas

```js
import { createCanvasRecorder } from "@grundyjs/canvas-take";
const recorder = createCanvasRecorder(canvas, { fps: 30 });
await recorder.start();
// Run your animation, then:
const { blob, extension, mimeType, durationMs } = await recorder.stop();
const url = URL.createObjectURL(blob);
// Use url in a video player or download link. Revoke it when no longer needed.
recorder.dispose();
```

`start` завершается после события start от MediaRecorder. `stop` ждёт последних
событий dataavailable и stop; повторные вызовы возвращают тот же promise.
При ошибках ожидающие операции отклоняются, принадлежащие рекордеру дорожки
останавливаются, а накопленные фрагменты освобождаются. `dispose` отменяет незавершённую
запись и допускает повторные вызовы. Каждый экземпляр записывает один раз.
Пока start ожидает завершения, состояние остаётся idle; повторный start отклоняется.

Порядок автоматического выбора формата: WebM VP9, VP8, обычный WebM, MP4.
При записи со звуком варианты VP9 и VP8 включают Opus. Явно заданный неподдерживаемый
MIME вызывает ошибку без скрытой смены формата. Результат содержит фактический MIME
и соответствующее расширение. FPS и битрейт — целевые значения, а не гарантии.
durationMs измеряет реальное время записи, а не длительность, прочитанную из файла.

Не меняйте размеры битовой карты canvas от start до stop. Масштабирование через CSS
допускается. Изменение размеров завершает запись ошибкой. Canvas должен оставаться
origin-clean. Захват экрана, пауза записи, покадровое кодирование видео и отправка
на сервер не поддерживаются. Фрагменты хранятся в памяти: ограничивайте длительность.
Если замедление фоновой вкладки недопустимо, вызывайте dispose при скрытии страницы.
Поддержка кодеков зависит от браузера и доступных ресурсов.

Разработка: Node.js 22+, `npm install`, `npm test`, `npm pack`. ESM и декларации
создаются в dist. `npm pack` автоматически пересобирает пакет; `npm publish`
запускает тесты до упаковки. Интеграционный пример ожидает AlgiViz в соседнем
каталоге и запускается через включённый в репозиторий локальный сервер.

См. [остановку MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/stop)
и [проверку формата](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static).
WebM от MediaRecorder может не содержать метаданные длительности: воспроизведение
работает, но плеер показывает неопределённую длительность. Для надёжной перемотки
или публикации отдельно перепакуйте контейнер. CanvasTake не переписывает его метаданные.

## Настройки и результат

| Настройка | Значение |
| --- | --- |
| `fps` | Обязательная положительная конечная целевая частота захвата |
| `videoBitsPerSecond` | Необязательный положительный конечный целевой битрейт кодировщика |
| `mimeType` | Необязательный явно заданный поддерживаемый MIME `video/webm` или `video/mp4`, включая кодеки |
| `audioTracks` | Необязательный список только для чтения из активных звуковых `MediaStreamTrack`; без него или с пустым списком запись идёт без звука |

`stop()` возвращает `{ blob, mimeType, extension, durationMs }`. Используйте рекордер
в try/finally и вызывайте `dispose()`, даже если анимация завершилась ошибкой.
Освобождайте object URL, когда они больше не нужны.

## Запись с озвучкой

Сведите звук в одну выходную дорожку Web Audio: несколько звуковых дорожек
поддерживает не каждый кодировщик. Декодируйте озвучку до начала записи.
Вызывайте код из обработчика действия пользователя, чтобы браузер мог возобновить
аудиоконтекст:

```js
async function recordNarration(canvas, narrationBytes) {
    const audio = new AudioContext();
    let recorder;
    let destination;
    try {
        await audio.resume();
        const buffer = await audio.decodeAudioData(narrationBytes);
        destination = audio.createMediaStreamDestination();
        const source = audio.createBufferSource();
        source.buffer = buffer;
        source.connect(destination);
        recorder = createCanvasRecorder(canvas, {
            fps: 30,
            mimeType: "video/mp4",
            audioTracks: destination.stream.getAudioTracks(),
        });
        const finished = new Promise(resolve => {
            source.addEventListener("ended", resolve, { once: true });
        });
        await recorder.start();
        source.start();
        // Run your canvas animation while the narration plays.
        await finished;
        return await recorder.stop();
    } finally {
        recorder?.dispose();
        destination?.stream.getTracks().forEach(track => track.stop());
        await audio.close();
    }
}
```

Для MP4 со звуком нужна поддержка кодировщика в браузере; явный запрос MP4
никогда не переключается на WebM. CanvasTake использует MediaRecorder напрямую
и не перекодирует результат. Воспроизведением звука и анимацией canvas управляет
приложение; они работают в реальном времени.

`video/mp4` выбирает контейнер, а не конкретные кодеки: браузер может записать
VP9/Opus в MP4. Если площадке нужны H.264/AAC, укажите MIME с кодеками, например
`video/mp4;codecs=avc1,mp4a.40.2`, и обработайте ошибку неподдерживаемого формата.

Для быстрой проверки в браузере после сборки запустите `node examples/server.cjs`
и откройте `http://127.0.0.1:3012/canvas-take/examples/audio.html`. Пример записывает
сгенерированный тон и движущийся canvas 1080×1920 с явно заданными H.264/AAC,
запрашивает остановку через две секунды, показывает результат и сохраняет его
как `canvastake-test.mp4` во временном каталоге сервера. Ранее проверенный результат
в локальном браузере: H.264 Constrained Baseline, прогрессивная развёртка 4:2:0,
стерео AAC-LC 48 кГц, 2,476 секунды и примерно 29,1 fps. Перекодирование и перепаковка
не использовались. Фактические длительность, частота кадров и поддержка кодеков
зависят от браузера и нагрузки во время выполнения.

Список аудиодорожек копируется при создании и повторно проверяется при start.
CanvasTake клонирует дорожки при start и при завершении, dispose или ошибке
останавливает только свои копии и дорожки захвата canvas. Исходными дорожками
и AudioContext владеет вызывающий код. Неожиданное завершение записываемой копии
вызывает ошибку записи. `stop()` исходной дорожки не останавливает её копию;
для завершения записи вызовите `recorder.stop()`. Окончание AudioBufferSource
также не завершает выходную дорожку.

## Покадровый экспорт GIF

Доступен с версии 0.3.0.

```js
import { createGifExporter } from '@grundyjs/canvas-take/gif';
import { createGifencEncoder } from '@grundyjs/canvas-take/gif/gifenc';

const controller = new AbortController();
const gif = createGifExporter({
    encoder: createGifencEncoder({ maxColors: 128, quality: 'high' }),
    repeat: 0,
    signal: controller.signal,
});
try {
    for (let time = 0; time < 6000; time += 50) {
        drawTimeline(time); // Your deterministic renderer draws into canvas.
        await gif.addFrame(canvas, 50);
    }
    drawTimeline(6000);
    await gif.addFrame(canvas, 2000); // Hold the final frame for two seconds.
    const blob = await gif.finish(); // image/gif; 8 seconds, 121 frames.
    // Download/preview blob; revoke any object URL when no longer needed.
} finally {
    gif.dispose();
}
```

`encoder` обязателен и передаётся приложением. Точка входа `/gif` не зависит от
кодека; `/gif/gifenc` — необязательный самостоятельный адаптер со встроенным
кодеком gifenc под MIT. Корневой импорт видео не загружает ни один GIF-модуль.
Адаптер можно заменить без изменения цикла экспорта.

| Настройка | Значение |
| --- | --- |
| `repeat` | По умолчанию `0`: бесконечно. `-1`: один просмотр. `1..65535`: дополнительные повторы после первого просмотра |
| `signal` | Необязательный AbortSignal; отмена отклоняет ожидающие операции и освобождает кодировщик |
| `background` | Тройка байтов RGB, по умолчанию `[255, 255, 255]`; прозрачность накладывается на непрозрачный фон |
| `maxColors` адаптера | Максимум цветов палитры на кадр: целое `2..256`, по умолчанию `256` |
| `quality` адаптера | `high` (по умолчанию, RGB565) или `fast` (RGB444); без дизеринга |

`addFrame(canvas, durationMs)` немедленно снимает копию 2D HTMLCanvasElement или
OffscreenCanvas, затем отдаёт управление перед кодированием. Дожидайтесь каждого
вызова перед следующим кадром или `finish()`. Все кадры должны иметь одинаковые
положительные размеры, не более 65535 по каждой оси — предел GIF. Длительности
должны быть конечными и находиться в диапазоне от 10 до 655350 мс; они округляются
до ближайших 10 мс. GIF-плееры могут увеличивать короткие задержки; 50 мс —
практичный шаг временной шкалы. Время рисования и реальное время кодирования
не влияют на длительность GIF. Canvas остаётся у приложения и не изменяется.
Для canvas с ограниченным доступом к пикселям операция завершается ошибкой чтения.

`finish()` требует хотя бы один кадр, возвращает Blob и освобождает кодировщик.
Каждый экземпляр создаёт один GIF. `dispose()` допускает повторные вызовы,
отменяет ожидающие операции и освобождает ресурсы кодировщика. Неверные данные
кадра, изменение размеров и ошибки кодировщика делают дальнейший экспорт невозможным.
Одновременные вызовы отклоняются, не отменяя текущую операцию. Возможные состояния:
`ready`, `encoding`, `finished`, `failed`, `aborted` и `disposed`.

Встроенный адаптер постепенно кодирует полные кадры с отдельными палитрами,
сохраняя сжатый результат вместо всех исходных кадров. Обработка каждого кадра
синхронна и выполняется в вызывающем потоке; отмена обрабатывается между кадрами.
Для тяжёлых кадров используйте готовый адаптер `/gif/worker`, OffscreenCanvas в Worker или передайте асинхронный
адаптер с Worker; автоматического пула Worker нет. Байты GIF и итоговый Blob
занимают память, поэтому ограничивайте размеры и число кадров. Размер файла
зависит от визуальной сложности; анимация шириной 800 px и длиной 6–10 секунд —
целевой сценарий, а не гарантия файла размером 2–3 МБ.

### Worker-адаптер и прогресс (0.4.0)

```ts
import { createGifExporter } from '@grundyjs/canvas-take/gif';
import { createGifWorkerEncoder } from '@grundyjs/canvas-take/gif/worker';

const gif = createGifExporter({
    encoder: createGifWorkerEncoder({ maxColors: 128, quality: 'high' }),
    totalFrames: 121,
    onProgress({ phase, framesEncoded, totalFrames, durationMs }) {
        console.log(phase, framesEncoded, totalFrames, durationMs);
    },
});
// Последовательно: await gif.addFrame(canvas, durationMs), затем await gif.finish().
```

Квантование и кодирование выполняются в отдельном module Worker. Чтение canvas
и наложение прозрачности на фон остаются в вызывающем потоке. Каждый экспортёр
владеет одним Worker и завершает его при успехе, ошибке, отмене или `dispose()`.
Буферы пикселей передаются без копирования; исходный canvas не меняется.
Требуется поддержка Worker; автоматического перехода к синхронному кодированию нет.

При прямом импорте в браузере размещайте `gif-worker.js`, `gif-worker-runtime.js`
и `gifenc.js` рядом, с MIME-типом JavaScript. Для сборщика проверьте, что Worker
и его зависимости попали в результат сборки. При необходимости скопируйте runtime
и `gifenc.js` в один публичный каталог и передайте `workerUrl: '/assets/gif-worker-runtime.js'`.
Путь пакета `/gif/worker-runtime` предназначен для разрешения адреса ресурса,
а не для импорта в основном потоке. Учитывайте same-origin и CSP `worker-src`;
Blob URL и встроенный код Worker не требуются.

`timeoutMs` по умолчанию равен 30000 мс **на каждый запрос**: запуск, отдельный кадр
и финализацию. При тайм-ауте, ошибке загрузки или передачи сообщения ожидающие
операции отклоняются, а Worker завершается.

`onProgress` работает с любым кодировщиком. Неизменяемый снимок приходит после
успешного кадра (`encoding`), перед финализацией (`finalizing`) и при результате
`finished`, `failed`, `aborted` или преждевременном `disposed`. Начального события нет.
`framesEncoded` и `durationMs` учитывают только завершённые кадры с округлёнными
длительностями GIF. Необязательный `totalFrames` — положительное безопасное целое
для отображения, а не ограничение числа кадров; без него поле отсутствует.
Полное число кадров ещё не означает завершение финализации. Процент и ETA
автоматически не вычисляются. Исключения наблюдателя игнорируются; из него можно
отменить или освободить экспортёр. `dispose()` после конечного результата
не создаёт дополнительного события.

### Подключение другого кодировщика

Реализуйте экспортируемый контракт `GifEncoderFactory`:

```ts
import type { GifEncoderFactory } from '@grundyjs/canvas-take/gif';

const encoder: GifEncoderFactory = ({ repeat }) => ({
    addFrame({ data, width, height, durationMs }) {
        // Pass the opaque RGBA snapshot to your codec; may return Promise<void>.
    },
    async finish() {
        // Return complete GIF bytes as Uint8Array.
        return encodedBytes;
    },
    dispose() {
        // Drop buffers, terminate owned Workers, settle pending operations.
    },
});
```

Каждый вызов фабрики должен создавать новый кодировщик и учитывать переданное число
повторов. Экспортёр вызывает методы последовательно и вызывает `dispose()` один
раз при успехе, ошибке или отмене. Адаптер может передать принадлежащий ему буфер
кадра в Worker; он должен освобождать ссылки на кадр после каждой операции
и поддерживать dispose во время ожидающей операции. Отмена немедленно отклоняет
операции экспортёра, но внешнюю работу очищает адаптер. Синхронную работу кодека
нельзя прервать в том же потоке. Исключения очистки подавляются, чтобы сохранить
основной результат операции.

После сборки запустите `node examples/server.cjs` и откройте
`http://127.0.0.1:3012/canvas-take/examples/gif.html` — отдельный пример покадрового
экспорта с отменой, предпросмотром и скачиванием. Обоснование выбора кодека
и измеренные размеры модулей приведены в [docs/gif-encoder.md](../docs/gif-encoder.md).

Если собранный AlgiViz находится в соседнем каталоге `algiviz`, откройте
`http://127.0.0.1:3012/canvas-take/examples/gif-bfs.html` для интеграции с настоящим
BFS. Ранее проверенный результат: 800×560, 141 кадр, 9 секунд с удержанием последнего
кадра 2 секунды, около 1,60 МБ. Пример использует существующие алгоритм и рендерер
AlgiViz и не изменяет тот проект.

## Использование в браузере и на сервере

Для записи нужен браузер с `canvas.captureStream`, `MediaRecorder` и `MutationObserver`.
Импорт модуля не обращается к этим API; создание рекордера проверяет поддержку
захвата и кодировщика. Реализации записи для Node.js нет. Поддержка кодеков
определяется во время выполнения, а не по названию браузера.

Интеграционный пример ранее проверен настоящей записью VP9 в 1920×1080.
Это не обещание, что любой браузер создаст WebM или MP4. Canvas с содержимым
из другого источника без CORS может оказаться недоступен для захвата.

## Выпуск версии

Запустите `npm test` и `npm run test:package`: последняя команда упаковывает архив,
устанавливает его в изолированное приложение и проверяет декларации TypeScript
и импорты во время выполнения. Архив содержит dist, README, LICENSE, CHANGELOG
и метаданные пакета. Исходный код и задачи:
[urffin/canvas-take](https://github.com/urffin/canvas-take). API версии 0.x может
меняться в следующих минорных релизах.

После успешного CI для коммита релиза опубликуйте стабильный GitHub Release
с тегом `v<package version>`. Workflow `npm-publish.yml` проверяет согласованность
версий, тестирует приложение с упакованным пакетом и публикует с OIDC/provenance.
Перед первым автоматическим релизом настройте npm trusted publisher для владельца
`urffin`, репозитория `canvas-take` и workflow `npm-publish.yml`. Токен npm
не используется. Публикация — отдельное действие сопровождающего проекта.
